# Кастомні Меблі

Сайт-візитка з прийомом заявок: заявка → база PostgreSQL → повідомлення в Telegram.
Стек: ASP.NET Core 10 (Blazor, серверний рендер), EF Core + Npgsql, Docker, Render.

```
src/KastomniMebli.Web/     сайт
  Components/Landing/      блоки лендінгу (креслення — SVG у WardrobeDrawing / KitchenDrawing)
  Leads/                   форма заявки: валідація, телефон, спам-захист, ендпоінт POST /zayavka
  Notifications/           Telegram
  Data/                    модель, DbContext, міграції
  appsettings.json         контакти, райони, команда, FAQ (секція "Site")
tests/KastomniMebli.Tests/ тести
```

## Запуск локально

Потрібно: .NET SDK 10 і PostgreSQL (локальний або зовнішній URL бази з Render).

```powershell
copy .env.example .env      # і вписати DATABASE_URL, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
dotnet run --project src/KastomniMebli.Web
```

Сайт відкриється на http://localhost:5155. Таблиці створюються самі при старті (EF-міграції).

Тести (база не потрібна):

```powershell
dotnet test
```

## Telegram-бот

1. У Telegram написати [@BotFather](https://t.me/BotFather) → `/newbot` → отримати токен → це `TELEGRAM_BOT_TOKEN`.
2. Створити групу (ти + брат), додати туди бота, написати в групі будь-що.
3. Відкрити `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — у відповіді `"chat":{"id":-100...}` → це `TELEGRAM_CHAT_ID`.
   Замість групи можна вказати кілька особистих id через кому (кожен має спершу написати боту `/start`).

## Ручна перевірка

1. Відкрити сайт на комп'ютері й на телефоні, пройтись по всіх розділах.
2. Надіслати заявку → має з'явитись «Дякуємо, <ім'я>!…», повідомлення в Telegram і рядок у таблиці `leads`:
   `select id, created_at, name, phone, furniture_types, telegram_sent_at, telegram_error from leads order by id desc;`
3. Невірний телефон (`123`) → червона підказка під полем.
4. Шоста заявка за годину з однієї адреси → «Забагато заявок…».
5. Тимчасово зіпсувати `TELEGRAM_BOT_TOKEN` → заявка все одно в базі, у `telegram_error` — причина.

## Деплой на Render

Автодеплой: push у гілку `main` → Render сам збирає Docker-образ.

Перший раз:
1. Render → **New → Blueprint** → вибрати репозиторій `kastomni-mebli` → Render прочитає `render.yaml`
   і створить сайт + базу. (Або створити Web Service вручну з Dockerfile і вказати `DATABASE_URL` існуючої бази.)
2. У налаштуваннях сервісу → **Environment** заповнити `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `Site__Phone`, `Site__Telegram`.
3. Після деплою відкрити `https://<сервіс>.onrender.com/healthz` → має бути `ok`.
4. Надіслати тестову заявку з телефона (мобільний інтернет) і з Wi-Fi: у таблиці `leads` поле `ip_hash`
   має відрізнятися — отже обмеження частоти рахує кожного клієнта окремо.

## CRM (`/crm`)

Замовлення, клієнти, оплати, витрати, частки, дашборд. Вхід — логін і пароль.

**Перший вхід.** У Render → kastomni-mebli → Environment задати `ADMIN_LOGIN` (латиницею), `ADMIN_PASSWORD`
(від 8 символів) і за бажання `ADMIN_NAME`. Після перезапуску сайт створить адміністратора — лише якщо
користувачів ще немає. Далі брата й монтажника додаєш сам у **Налаштування → Користувачі**.

**Ролі:**
- адміністратор — усе, включно з користувачами;
- менеджер — замовлення, клієнти, гроші, дашборд, шаблон часток;
- монтажник — лише призначені йому замовлення: адреса, дати, телефон клієнта, креслення. Гроші не бачить.

**Частки.** Налаштування → «Частки за замовчуванням»: хто, як рахувати (% від договору / % від матеріалу /
фіксована сума), скільки. Копіюються в кожне нове замовлення, у замовленні їх можна змінити.
«Виплачено» фіксує суму на момент виплати.

**Дашборд місяця:**
- заявки / замір / договір — за замовленнями, створеними в місяці;
- виручка й витрати — за датою оплати/витрати;
- прибуток і заробіток учасників — за замовленнями, завершеними в місяці;
- «винні» — невиплачені частки завершених замовлень; «нараховується» — по замовленнях у роботі.

**Файли** (креслення PDF/DWG/DXF, фото, до 20 МБ) лежать на постійному диску Render (`/var/data/files`),
у базі — лише опис. Резервна копія диска — у Render → Disks → Snapshots.

**Telegram:**
- заявка з сайту й нове замовлення — у загальний чат (`TELEGRAM_CHAT_ID`) з посиланням на CRM;
- статус «Монтаж» — монтажнику особисто;
- щодня о 18:00 — нагадування про завтрашні заміри й монтажі.

Особисті сповіщення приходять, якщо в користувача вказано Telegram chat id (людина пише боту `/start`,
id дізнається в @userinfobot).

## Портфоліо (`/roboty`)

CRM → Портфоліо: робота = назва, тип, місто, опис, фото. «Показувати на сайті» — з'являється на `/roboty`;
«На головній» — у блоці на 6 місць (далі добираються найновіші); «Приклад для меблярів» — на сторінці B2B.
Фото стискаються ще на телефоні (до 1920 px), GPS з них прибирається.

## Для меблярів (`/dlya-meblyariv`)

Сторінка B2B-послуг конструктора з формою (до 10 файлів, до 20 МБ кожен). Заявка стає замовленням
«Креслення (B2B)» у CRM (свій цикл статусів, без часток), сповіщення — адміністратору особисто.
Ціни — CRM → Налаштування → «Ціни для меблярів» (порожнє поле не показується).

## Автопостинг (CRM → Пости)

Пишеш текст, додаєш до 10 фото, обираєш мережі, «зараз» або на час. Кожна мережа публікується окремо:
збій в одній не зупиняє інші; помилка — у журналі поста й тобі в Telegram, кнопка «Повторити».
Фото на телефоні обрізаються під Instagram (від 4:5 до 1.91:1) і зменшуються до 1440 px.

**Telegram-канал:** додати бота (той самий `TELEGRAM_BOT_TOKEN`) адміністратором каналу з правом
«Публікація повідомлень»; `TELEGRAM_CHANNEL_ID` = `@назва_каналу`.

**Facebook + Instagram (Meta Graph API v26.0):**
1. Facebook-сторінка, ти — її адмін; бізнес-портфоліо на business.facebook.com, сторінка в ньому.
2. Instagram → професійний акаунт (Business), прив'язати до сторінки.
3. developers.facebook.com → створити застосунок типу **Business**, підключити до бізнес-портфоліо;
   use cases: керування сторінкою + Instagram (через Facebook Login). App Review **не потрібен** — застосунок
   лишається в режимі Development, публікуємо лише у власні акаунти.
4. Дозволи: `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `business_management`,
   `instagram_basic`, `instagram_content_publish`.
5. Токен: Business Settings → System users → додати → призначити сторінку й Instagram → Generate token
   (термін «Never») → `GET /v26.0/me/accounts` → токен сторінки = `FB_PAGE_ACCESS_TOKEN`.
   Перевірити в Access Token Debugger: «Expires: Never».
6. `FB_PAGE_ID` — id сторінки; `IG_USER_ID` — з `GET /v26.0/{FB_PAGE_ID}?fields=instagram_business_account`.
7. `Site__BaseUrl` має бути публічною https-адресою — Meta забирає фото за посиланням.

Обмеження Instagram: лише з фото, до 2200 символів, до 30 хештегів, до 100 постів на добу.

## Звідки приходять клієнти (мітки)

До рекламних посилань додавай мітки — тоді в CRM і на дашборді видно, яка реклама приводить клієнтів:

```
https://kastomni-mebli.onrender.com/?utm_source=instagram&utm_campaign=kuhni_zhovten
https://kastomni-mebli.onrender.com/?utm_source=olx&utm_campaign=shafy
```

Без міток канал визначається за сайтом, звідки перейшли (instagram, facebook, google…), або «direct».
Браузер запам'ятовує **перший** візит, тож мітка не губиться, якщо людина походила сайтом.
Витрати на рекламу вноси в CRM → Ще → **Загальні витрати** (категорія «Реклама») — дашборд порахує ціну
однієї заявки й скільки гривень оплат принесла гривня реклами.

## Облік

- **Журнал змін грошей** (CRM → Ще → Журнал, і внизу картки замовлення): хто, коли й що змінив в оплатах,
  витратах, частках, сумі договору. Записи не редагуються й не видаляються.
- **Виплатити все** — на дашборді в таблиці «Учасники»: закриває всі невиплачені частки людини в завершених замовленнях.
- **Причина скасування** — обов'язковий вибір при скасуванні; статистика «Чому втрачаємо клієнтів» на дашборді.
- **Вивантаження** — на дашборді: оплати, витрати, виплати часток, замовлення за місяць (CSV, відкривається в Excel).
- **Календар** — заміри, монтажі й терміни B2B на тиждень; монтажник бачить лише свої.

## Сайт без Render

CRM → Ще → **Сайт**: телефон, Telegram, райони, ролі команди, часті питання. Діє одразу після збереження.
Значення з `appsettings.json` / змінних Render лишаються типовими («Повернути типові»).

## CRM як застосунок на телефоні

Відкрити `/crm` у Chrome (Android) → меню ⋮ → «Додати на головний екран»; на iPhone — Safari → «Поділитися» →
«На початковий екран». CRM відкриватиметься без адресного рядка, як окремий застосунок.

## Якщо сайт ліг — сповіщення

Безкоштовно через UptimeRobot (перевірка кожні 5 хвилин):
1. uptimerobot.com → зареєструватись → **Add New Monitor** → тип HTTP(s),
   URL `https://kastomni-mebli.onrender.com/healthz` (відповідає «ok», лише якщо живі і сайт, і база).
2. **Alert Contacts** → додати Telegram (за їхньою інструкцією) або email.

## Налаштування

| Що | Де |
|---|---|
| Телефон, Telegram на сайті | `Site__Phone`, `Site__Telegram` (Render) або `appsettings.json` |
| Райони, ролі команди, FAQ | `appsettings.json` → `Site` |
| Ліміт заявок з однієї IP за годину | `Leads:RateLimitPerHour` (5) |
| Мінімальний час заповнення форми, с | `Leads:MinFillSeconds` (3) |
| Адреса сайту для посилань у Telegram | `Site__BaseUrl` |
| Папка файлів CRM, ліміт розміру | `Files__Root`, `Files__MaxSizeMb` (20) |
| Шаблон часток, що вважати матеріалом | CRM → Налаштування |
